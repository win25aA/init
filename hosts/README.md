# Компьютеры (hosts)

Каждая папка здесь — отдельный компьютер. Общие программы и настройки лежат в `system/` и `home/`, а в `hosts/` — только отличия железа. Имя папки становится именем компьютера. `_template` — шаблон для ручной настройки.

## Новый ПК с уже установленной NixOS

Скрипт `setup-new-pc.sh` создаёт новый host, получает настройки железа и проверяет сборку. Программы он берёт из общего конфига — отдельного списка в скрипте нет.

На новом ПК, в обычном терминале от своего пользователя:

```bash
# Если Git ещё не установлен:
nix-shell -p git

git clone -b feature/portable-setup https://github.com/win25aA/init.git ~/init
cd ~/init
bash setup-new-pc.sh
```

Для проверки без применения можно запустить `bash setup-new-pc.sh --check`. Он создаст и добавит host в Git staging текущей копии и соберёт конфиг, но не переключит систему и не запишет загрузчик. Для пробного запуска на основном ПК используй отдельный клон репозитория, не `/etc/nixos`. Сборка может занимать место в Nix store.

Нужны интернет и доступ к `sudo`. Папка `~/init` не должна существовать; если она есть, выбери другое свободное место для клона. Не запускай скрипт через `sudo` целиком: он сам запросит его для нужных команд.

Скрипт определяет BIOS/UEFI и распознаваемые PCI-видеокарты. Он может задать вопросы, если не уверен: например, попросит подтвердить диск GRUB в режиме BIOS или совместимость NVIDIA с драйвером 580. Для необычного железа, гибридной графики и нестандартного EFI может потребоваться ручная настройка. В Hyprland и Sway мониторы включаются автоматически, без переноса расположения мониторов старого ПК. Взятый из `universal` bspwm пока содержит настройки мониторов старого ПК; его перенос не проверен. В Noctalia отдельные виджеты тоже привязаны к именам старых мониторов и могут потребовать перенастройки.

После создания host скрипт покажет обнаруженные файловые системы и проверит сборку. Он добавляет только новые файлы host в Git staging, но **не делает коммит и не пушит**. Применение — только после отдельного подтверждения `APPLY`; загрузчик при этом будет установлен на выбранный диск.

Если репозиторий был не в `/etc/nixos`, скрипт перед применением сохраняет прежний `/etc/nixos` в `/etc/nixos.backup-ДАТА` и копирует туда репозиторий: Noctalia, обои и команды сейчас используют именно этот путь. Он не станет автоматически заменять симлинк `/etc/nixos` или расположенный там другой Git-репозиторий. Исходная копия репозитория останется на месте, но дальнейшие изменения нужно делать в `/etc/nixos`.

Системные настройки и службы при применении заменяются настройками общего конфига. Сохранённая копия `/etc/nixos` — не резервная копия личных данных. Программы, входы в аккаунты, файлы и настройки, которые не описаны в конфиге, отдельно не переносятся. Сделай резервную копию важных данных и имей возможность откатиться к предыдущему поколению NixOS.

Пользователь конфига — `winarowk`. Если его ещё не было, после применения задай ему пароль командой `sudo passwd winarowk` до выхода из текущей сессии. Пароль в Git не записывается.

**Важно:** обычная команда `nrs` после успешной сборки добавляет файлы в Git и пушит их. Она может отправить и созданный host, если он ещё не закоммичен. Скрипт начальной подготовки `nrs` не запускает.

## Ручная настройка

Можно скопировать `hosts/_template` в новую папку, получить `hardware-configuration.nix` через `nixos-generate-config --show-hardware-config` и вручную заполнить GPU, загрузчик и `system.stateVersion`. Добавь новые файлы в Git, чтобы flake их увидел. Не используй `hardware-configuration.nix` или диски от другого ПК.

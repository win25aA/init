# bspwm + оригинальная Polybar Varinka + Matugen для твоего NixOS

Подготовлено по приложенным configuration.nix, home.nix, matugen.nix и sway.nix.
Sway, Hyprland, Noctalia, их импорты и flake inputs сохранены. Flake.lock не обновляется.
Это файлы для установки, а не изменения, уже применённые к твоему компьютеру.

## Это исходная Varinka, не перерисовка

Основа: gh0stzk/dotfiles, первоначальный коммит с Varinka:
https://github.com/gh0stzk/dotfiles/tree/a3f0ea1f7310a89fb1fbcdad9af6e96b15488867/config/bspwm/rices/varinka

В `modules/bspwm/upstream/` лежат НЕИЗМЕНЁННЫЕ config.ini, modules.ini, Theme.sh,
GPL-3.0 LICENSE, SHA256 и точная ревизия. Theme.sh сохранён для происхождения,
но **не запускается**: он делал sed/запись в чужие конфиги, несовместимые с Home Manager.
`ADAPTATION.patch` показывает каждое изменение рабочих INI относительно оригинала.

Сохранены без изменений:
- bar/varinka-bar, ширина 96%, высота 35, offset-x 2%, offset-y 3;
- радиус панели 8, рамка 2, оригинальные отступы;
- все четыре объявления оригинальных шрифтов Maple Mono NF;
- состав и порядок modules-left, modules-center, modules-right;
- оригинальные значки, разделители и раскладка элементов.

Адаптированы только необходимые интеграции:
- цвета читаются из Matugen вместо фиксированной палитры;
- system.ini создаётся для текущих устройств, вместо Arch-скрипта;
- OpenApps и Arch Updates заменены локальными действиями;
- MPD-кнопки с теми же значками и тем же местом управляют MPRIS через playerctl;
- рабочие столы расширены с 6 до 10; надпись пустого окна — NixOS;
- старый необязательный Weather не включается, плагины не переносятся.

### Два физических ограничения

1. В X11 существует один XEmbed-трей на X screen. У обеих панелей остаётся
   оригинальный tray-модуль, но значки достанутся только одной. Основная панель
   запускается первой. Дублирования одних и тех же tray-окон на обоих экранах нет.
2. На 1024×768 полный оригинал может не поместиться: Polybar обрежет часть контента.
   Ничего автоматически не скрывается, шрифт не уменьшается, модули не упрощаются.
   `pin-workspaces = true` оставлен как у автора: каждый бар показывает столы своего монитора.
   Батарея показывается только если физически существует; на стационарном ПК Polybar
   может написать в лог, что battery-модуль не удалось загрузить. Это не удаление модуля.

## Что внутри

- `modules/bspwm.nix` — Home Manager, пакеты, bspwm, настройки мониторов.
- `modules/bspwm/` — оригинальный Polybar с минимальной адаптацией, бинды, Picom,
  шаблон Matugen и X11-помощники.
- `system/bspwm-session.nix` — минимальный системный модуль: сессия SDDM,
  PAM для блокировки, интеграция Blueman, GTK portal для bspwm.
- `configuration.nix` — твой файл + один import системного модуля.
- `home.nix` — твой файл + один import Home Manager-модуля.
- `modules/matugen.nix` — твой файл + один шаблон/хук, существующие шаблоны сохранены.
- `INTEGRATION.patch` — точечный diff трёх изменённых пользовательских файлов.
- `tests/` и `VALIDATION.md` — проверки и их границы.

Системный модуль необходим: одной пользовательской конфигурацией Home Manager
нельзя корректно зарегистрировать сессию SDDM и PAM. Сам рабочий стол управляется HM.
Новые файлы не требуют нового flake input, изменения драйвера NVIDIA или nixpkgs.

## Установка

**Если с момента отправки файлы менялись, не перезаписывай их целиком:** внеси
три небольших изменения из INTEGRATION.patch вручную и скопируй только новые модули.

Сначала сделай резервную копию затрагиваемых файлов:

```sh
backup="$HOME/nixos-before-bspwm-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup/modules"
cp /etc/nixos/configuration.nix /etc/nixos/home.nix "$backup/"
cp /etc/nixos/modules/matugen.nix "$backup/modules/"
printf 'Backup: %s\n' "$backup"
```

Из распакованной папки `varinka-bspwm-hm`, если исходные файлы не менялись:

```sh
sudo mkdir -p /etc/nixos/system /etc/nixos/modules/bspwm
sudo cp configuration.nix home.nix /etc/nixos/
sudo cp modules/bspwm.nix modules/matugen.nix /etc/nixos/modules/
sudo cp -a modules/bspwm/. /etc/nixos/modules/bspwm/
sudo cp system/bspwm-session.nix /etc/nixos/system/
```

Если `/etc/nixos` — Git-репозиторий, добавь новые файлы в индекс, иначе flake
их не увидит. Это не требует коммита и ничего не отправляет в сеть:

```sh
cd /etc/nixos
git add configuration.nix home.nix modules/bspwm.nix modules/bspwm \
  modules/matugen.nix system/bspwm-session.nix
git diff --cached --stat
```

Сборка и безопасное переключение при следующей загрузке:

```sh
sudo nixos-rebuild build --flake /etc/nixos#winarowk
sudo nixos-rebuild boot --flake /etc/nixos#winarowk
```

Затем сохрани работу и перезагрузись. В SDDM выбери **bspwm-hm**
(название может отображаться с префиксом `none+`). Sway и Hyprland остаются
в выборе сессий. `boot`, в отличие от `switch`, не перезапускает SDDM в текущей сессии.
`nix flake update` для этого переноса запускать не нужно.

### Мониторы: что проверить при первом входе

Сохранена схема Sway:
- основной: 1440×900, около 74.98 Гц, позиция 0×0, столы 1–5;
- второй: 1024×768, около 70.07 Гц, позиция 1440×355, столы 6–10.

**Имена X11-выходов пока не известны**. Первоначально скрипт ищет их по наличию
нужного режима. При неоднозначности использует доступный выход и пишет предупреждение.
Он НЕ создаёт modeline и НЕ заставляет монитор работать на неподтверждённой частоте.
Если нет подходящей частоты, используется штатная частота режима.

В bspwm выполни:

```sh
xrandr --query
cat ~/.local/state/varinka/outputs.json
```

Укажи точные имена в начале `/etc/nixos/modules/bspwm.nix`:

```nix
primaryOutput = "DVI-D-0";  # пример, не готовое имя твоего выхода
secondaryOutput = "HDMI-0"; # пример
```

После изменения Nix-файла нужен rebuild. `Super+Shift+C` перечитывает уже
сгенерированный конфиг, но не заменяет Nix-сборку. Для новых названий/настроек
сессии надёжнее повторный вход. Горячее подключение мониторов отдельно не автоматизировано;
после него можно вызвать `varinka monitors && varinka bars`.

## Matugen и обои

`Super+Shift+W` открывает Rofi с превью картинок из `/etc/nixos/wallpapers`.
Выбор запускает строго такую последовательность:

1. `matugen image FILE --type scheme-content --source-color-index 0`;
2. обновление твоих существующих шаблонов и нового `varinka-colors.json`;
3. генерация цветов Polybar, Rofi, Dunst, bspwm и блокировки;
4. feh применяет одну картинку на обоих мониторах;
5. путь сохраняется для следующего входа.

Если Matugen завершился с ошибкой, новые обои не устанавливаются. Сам Matugen
не транзакционный: при ошибке один из его прежних шаблонов мог уже успеть записаться.
Выбор обоев сериализован, чтобы два параллельных запуска не перемешивали палитры.

Начальная картинка — та же, что в твоём Noctalia:
`/etc/nixos/wallpapers/wallpaperflare.com_wallpaper.jpg`. Если файла нет, выбери другой.

Можно вызвать напрямую, без проблем с пробелами в пути:

```sh
varinka wallpaper '/etc/nixos/wallpapers/My wallpaper.jpg'
```

Результаты хранятся в `~/.local/state/varinka/`, а не пишутся поверх Nix-store
или HM-ссылок. Хук Matugen в Sway/Hyprland тоже обновляет файлы цветов, но
**не запускает** там Picom, Polybar, Dunst и не обращается к Xwayland-bspwm.
Полная обновлённая палитра применяется при следующем входе в bspwm.
Новые цвета перечитываются работающими Kitty на текущем DISPLAY; остальные старые
приложения могут требовать перезапуска/своего механизма обновления темы.

В твоём Kitty после `matugen-colors.conf` ещё подключается `current-theme.conf`.
Я намеренно не менял kitty.nix. Если этот старый файл содержит цветовые настройки,
он может перекрывать Matugen: убери/очисти именно этот include после проверки файла.
Это касается и существующих Wayland-сессий, поэтому автоматически его не удалял.

## Замены Noctalia

| Функция | Реализация |
|---|---|
| Launcher | Rofi drun |
| Обои | Rofi с превью + feh + обязательный Matugen |
| Центр управления | Rofi-меню: звук, сеть, Bluetooth, обои, буфер, уведомления, ночной свет, скриншоты, сессия |
| Уведомления | Dunst, история и «не беспокоить» |
| Скриншоты | Flameshot, PNG в `~/Pictures` |
| Питание/выход | Rofi, подтверждение опасных действий |
| Блокировка | i3lock-color + NixOS PAM |
| Блокировка перед сном | xss-lock с передачей sleep inhibitor FD |
| Буфер | clipmenu + Rofi, только текст, история в XDG_RUNTIME_DIR |
| Ночной свет | Redshift, переключение 4500 K / сброс |
| Громкость и микрофон | PipeWire/wpctl + OSD-уведомление Dunst |
| Аудиоустройства | pavucontrol |
| Сеть | nm-applet + редактор соединений NetworkManager |
| Bluetooth | Blueman |
| Музыкальные кнопки | playerctl/MPRIS, в том числе Spotify |
| Календарь/карточка системы | небольшие Rofi-окна по клику на исходные значки |
| Агент подтверждения прав | lxqt-policykit-agent, только в bspwm |
| Тени, скругления, blur | Picom GLX, радиус окон 10 |

Это НЕ одна оболочка как Noctalia: центр управления — меню действий,
а не панель с ползунками. История Dunst не сохраняется после завершения процесса.
Clipboard может содержать секреты: даже временная история хранит скопированный текст.
Её можно отключить через `clipboardHistory = false;` в bspwm.nix.

Скриншот целиком сохраняется сразу. Для области открывается редактор Flameshot:
выдели область, при необходимости дорисуй и **подтверди**, чтобы PNG сохранился.
Отмена ничего не записывает. Автоматическое копирование изображения в буфер не включено.

Автоматический таймаут блокировки не навязан (`autoLockSeconds = 0`).
Блокировка вручную и перед сном включены. При желании задай таймаут в секундах.
Перед тем как полагаться на неё при сне, обязательно проверь ручную блокировку
и пробуждение на своём железе.

**Не переносились:** погода/виджеты рабочего стола, Wallhaven, PrismLauncher и
остальные плагины, редактор lockscreen, оформление всех GUI Noctalia.
Запись экрана не переписывалась: установленный у тебя gpu-screen-recorder остаётся,
но его работу и разрешения под X11 нужно проверить отдельно.
Яркость внешних мониторов не привязывалась к brightnessctl: обычно для неё нужен
DDC/CI, поддержка монитора и отдельное согласование доступа.

Порядок колеса следует биндам Sway: button4 → prev.local, button5 → next.local.
Глобальные захваты мыши sxhkd не полностью эквивалентны `--whole-window` Sway:
они работают и над рабочим столом. Столы bspwm постоянные, а не динамические как в Sway.
Sway `gaps inner/outer` и модель зазоров bspwm не абсолютно одинаковы:
выставлены window_gap 5 и padding 10, плюс место панели через EWMH strut.

## Модуль обновлений

Изначальный значок обновлений сохранён, но Arch Updates больше не запускается:
- `?` — не проверялось/ошибка;
- `0` — локальный nixpkgs в flake.lock совпадает с текущим nixos-unstable;
- `↑` — ревизии отличаются (НЕ количество доступных пакетов).

Левый клик проверяет метаданные nixpkgs; правый показывает пояснение.
Проверка не пишет flake.lock, не выполняет rebuild и не запускает sudo.
Она не проверяет остальные flake inputs и не доказывает, что новая ревизия тебе подходит.

## Диагностика

```sh
cat ~/.local/state/varinka/session.log
cat ~/.local/state/varinka/picom.log
cat ~/.local/state/varinka/dunst.log
ls ~/.local/state/varinka/polybar-*.log
varinka reload-colors
varinka bars
```

Если NVIDIA + Picom дают артефакты, не меняй драйвер вслепую: пришли picom.log,
вывод `xrandr --query` и описание проблемы. Здесь включены GLX, vsync и dual_kawase;
реальная совместимость с твоей картой/legacy_580 не проверена на этом компьютере.
Размытие видно у полупрозрачных окон, например у твоего Kitty с opacity 0.6.
Непрозрачные приложения принудительно прозрачными не делаются.

Не запускай одновременно графические сессии одного пользователя на разных VT:
они делят пользовательский D-Bus, сервер уведомлений и часть состояния приложений.
Обычное переключение через выход/вход SDDM поддерживается.

## Откат

Если новая сессия не работает, выбери Sway/Hyprland в SDDM. Если проблема затрагивает
всю загрузку — предыдущую генерацию NixOS в GRUB.
Для удаления интеграции восстанови три файла из резервной копии, пересобери систему
и войди заново. Новые файлы можно удалить после удаления их import.
Существующие Wayland-файлы и Noctalia не заменялись.

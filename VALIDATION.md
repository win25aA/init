# Результаты проверки

Этот документ описывает проверки ранее собранного polished-архива.
Это не заявление о повторной полной сборке текущего Git-репозитория.
Медиа и локальные журналы из архива не дублируются в Git.

## Версии

Использованы версии из присланного `flake.lock`:
- nixpkgs `c59305bab2065cfecc4944690d9eedbb56f3a9fa`;
- Home Manager `acd21c5a3420a9d5fd0ed06299b10828267ef9ba`.

Lock-файл не обновлялся. Неиспользуемый input Hyprland оставлен во flake только
для сохранения исходного lock-файла; модуль Hyprland не импортирован и сессия не включена.

## Автоматические проверки

- Все Nix-файлы прошли разбор tree-sitter-nix; Python-файлы — py_compile.
- Home Manager: успешная оценка activationPackage с реальными присланными
  fastfetch.nix/nodejs.nix (без заглушек для этих модулей).
- NixOS: успешная оценка `system.build.toplevel.drvPath`, сессия `none+bspwm`, PAM `i3lock`.
- В отдельной копии для системной оценки использованы **только тестовые**
  hardware-configuration.nix и каталоги тем SDDM/GRUB, так как они не приложены.
  Эти заглушки НЕ включены в архив. Логотип fastfetch имеет резервный builtin-вариант.
- Собраны пакеты `bspwm-desktop` и `bspwm-scratchpad`, включая проверки
  bash/ShellCheck, которые выполняет `writeShellApplication`.
- 15 Python-тестов: палитра всех компонентов, фильтрация/миниатюры обоев,
  сохранение/изображения уведомлений, исключение OSD, непрочитанные,
  состояние DND/CopyQ при блокировке (с mock-процессом), статические параметры
  Flameshot, отказ сети, успешное применение обоев и откат при ошибке/таймауте.
- `preflight.sh` прошёл `bash -n`.

Первая полная оценка NixOS была прервана с кодом 137 при параллельной компиляции.
После окончания компиляции отдельная ограниченная по времени оценка завершилась
успешно. Предупреждения: старое имя параметра DNSOverTLS из исходного файла и
`stdenv.isLinux` из внешнего input. Это предупреждения, не ошибки оценки.

## Проверки обновлённого оформления в настоящем X11

Не браузерный макет: Xvfb + bspwm + Picom 13 + Polybar + Rofi + Dunst.

- Проверены 1440×900 и 1024×768, включая шесть карточек обоев на малом экране.
- Настоящий Matugen сгенерировал палитру из демонстрационного изображения,
  а не из фиксированного серого seed. Пользовательские шаблоны сохранены.
- Убраны глифовые торцы капсул и фрагменты фоновой заливки Polybar.
- Осмотрены новые снимки панели, меню, уведомления и карточек: реальные
  прозрачные сглаженные углы, единые рамки и отступы, без чёрных квадратных углов.
- Проверены динамическое число рядов и уменьшение карточек при высоте ≤800 px.
- В виртуальном Xvfb нет GLX. Эффекты проверены на **Picom xrender + kernel blur**,
  выбранном через тестовую настройку compositorBackend. В Nix-модуле по умолчанию
  остаётся GLX + dual_kawase для реальной видеокарты; этот backend здесь не проверен.
- Неподходящая тестовая комбинация xrender + blur-background=true + blur-method=none
  приводила к падению Picom. Исправлено: xrender теперь получает kernel blur.
- Для устранения остатков теней после закрытия включена полная перерисовка.
- Записано **реальное X11-видео** 1440×900/30 fps с появлением/закрытием меню
  и уведомления, осмотрены ключевые кадры. Picom остался запущенным без ошибок.
- Дополнительные тесты проверяют отсутствие шрифтовых капсул, прозрачные углы
  миниатюр, пресеты анимаций, совместимый blur и отключение движения.

Проверки функций предыдущего этапа: Dunst принял FDO Notify; D-Bus-monitor
сохранил уведомления в SQLite, включая запуск с упакованными Python-зависимостями.
CopyQ loadTheme/maxitems/monitoring и маски углов Python/Xlib прошли runtime-проверки.
Эти проверки не заменены утверждением о проверке реального оборудования.

В `validation/previews/` отдельно выданного polished-архива — осмотренные снимки и видео. Фон создан
для демонстрации; сетка использует его разные кадрирования (для шести карточек —
дубликаты этих трёх примеров). Название трека — тестовое. Само изображение
в `demo/lake.jpg` этого архива необязательно, автоматически не устанавливается.
В Xvfb нет настоящего звукового сервера/трея твоих приложений и user-systemd с
Redshift: поэтому звук не показан, а меню сообщает «ночной режим: выкл».
В NixOS ночной режим включён по умолчанию. Настоящий пользовательский HOME/буфер
не использовался.

## Что не подтверждено на реальной машине

- Полная сборка и загрузка твоей NixOS: нужна проверка на твоём железе с реальными
  hardware-configuration.nix, темами, локальными файлами и доступностью всех пакетов.
- Реальные NVIDIA/выходы/частоты, GLX Picom, физическая яркость, Redshift/gamma,
  Bluetooth/сеть/звук, захват/запись экрана и PAM-разблокировка после сна.
- **Захват Flameshot не запускался.** Зависшая проверка старого чата не повторялась.
  Проверены конфигурация и наличие зависимости, а не успешный захват изображения.
- Нет утверждения о пиксельном совпадении Noctalia: это X11-аналоги функций.

Перед `switch` выполни команды сборки из README. Не удаляй предыдущие поколения.

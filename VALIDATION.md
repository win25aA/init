# Что проверено

## Реальное вычисление Nix, без установки

Использованы ровно ревизии приложенного flake.lock:

- nixpkgs: `a799d3e3886da994fa307f817a6bc705ae538eeb`;
- Home Manager: `acd21c5a3420a9d5fd0ed06299b10828267ef9ba`.

Успешно вычислены:

1. `home-manager.lib.homeManagerConfiguration(...).activationPackage.drvPath`
   для новых bspwm.nix + расширенного matugen.nix.
2. Та же активационная derivation для полного приложенного home.nix:
   Sway, Hyprland, Kitty, Fish, Fastfetch, Matugen, Noctalia, Node.js, btop + bspwm.
   Единственный отсутствующий файловый ресурс — wallpapers/.face, который использует
   исходный fastfetch.nix — в ИЗОЛИРОВАННОЙ тестовой копии заменён картинкой 1×1.
   Эта подстановка не входит в архив, пользовательские ресурсы не заменяются.
   У Nixpkgs включён allowUnfree; extraSpecialArgs.inputs для HM — пустой набор,
   поскольку приложенные HM-модули не читают flake inputs.
3. `nixpkgs.lib.nixosSystem(...).config.system.build.toplevel.drvPath`
   для системного bspwm-session.nix в минимальной тестовой NixOS-конфигурации.
   Xorg включён; контейнерный boot выбран только для проверки, не в файлах пользователя.

Проверены синтаксис пяти изменённых/новых Nix-файлов и TOML Matugen.
Шесть исходных шаблонов Matugen сохранены. Новый шаблон имеет index=100:
его post_hook выполняется после старых шаблонов.

Отдельно сверены CLI и поля конфигурации с Matugen 4.0.0, указанным в закреплённом
Nixpkgs: `--source-color-index`, `index`, `post_hook` поддерживаются. Комментарий
исходного пользовательского файла упоминает 4.1.0; его содержимое не переписывалось.

## Локальные тесты — 12/12

- разбор Xrandr с режимами и частотами;
- генерация Polybar/Rofi/Dunst из палитры;
- отсутствие обращений к X11 при post_hook в Wayland;
- отклонение некорректной палитры с сохранением предыдущих файлов темы;
- ошибка Matugen не меняет обои;
- Matugen выполняется до feh, пробелы в имени файла не превращаются в shell-команду;
- отменённый скриншот не создаёт пустой файл;
- PNG сохраняется в Pictures;
- музыкальные контролы сохраняют исходные значки и вызывают MPRIS;
- файловый дескриптор sleep inhibitor передаётся в i3lock-color;
- повторное назначение мониторов не сбрасывает рабочие столы;
- размеры/шрифты/списки модулей исходной панели неизменны;
- SHA256 сохранённых исходников совпадают с загруженными файлами автора.

Некоторые близкие проверки объединены в один unittest. Внешние приложения
в unit-тестах подменены, тесты не управляют реальным рабочим столом.

Запуск тестов из распакованного каталога:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

## Что НЕ проверено

- Это **не полная сборка и не nixos-rebuild** исходной системы пользователя.
  Сторонние flake inputs, тема SDDM, тема GRUB и физические ресурсы не пересобирались.
- Пакеты не собирались и не запускались на твоём компьютере.
- Настоящий Xorg с NVIDIA legacy_580, реальные названия выходов/EDID/частоты.
- Реальный рендер Polybar, наличие места на 1024×768 и вид каждого glyph шрифта.
- Реальная работа Flameshot, D-Bus уведомлений, PAM, сна и пробуждения.
- GLX blur/vsync Picom на твоей видеокарте.
- Права записи/наличие каталогов и изображений в твоём /etc/nixos.

Поэтому сначала нужен локальный `nixos-rebuild build`, затем вход в bspwm-hm,
проверка ручной блокировки и вывод `xrandr --query`. Не полагайся на блокировку
перед сном до её проверки на реальной системе.
